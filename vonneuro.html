vonNeuro: an operating system for heterogeneous, physical computing

vonNeuro is an open, experimental project to build an operating system for computers made of matter. It aims to run programs on p-bits, annealers, memristive networks, neuromorphic chips, analog circuits, GPUs, ordinary CPUs and, eventually, living neural cultures, all from a single language. Its first working piece, vonNeuro Messenger, already puts real laboratory devices online: anyone can send jobs from a browser or a Python script and get back the measured result, with raw data included. It is developed in collaboration with the Institute for Nonequilibrium Phenomena (INEP), a nonprofit research institute. For now it is free, and I cover the running costs myself.

Why I am building this

I am a memristive-network theorist. When I was at Los Alamos, I found it surprisingly hard to get hold of hardware and simply play with it myself. I have come to believe that direct, hands-on access is key to progress. Real devices are noisy, they drift, and they have hysteresis and quirks that simulations smooth over. You only learn to program them by running code on them.

My working assumption is that the future of computing is heterogeneous. CPUs already share work with GPUs and accelerators. Next to them, a growing family of physical processors computes by letting matter relax, fluctuate or respond, rather than by stepping through instructions. These include analog circuits, memristive networks, stochastic samplers, quantum annealers and photonic devices. Some will sit next to us and some will live in the cloud. Today we write code as if it will always run on a CPU. Instead, we should be able to state what a task needs and call whichever processor suits it: a sampler for a statistical problem, an analog resource for filtering or evolving a signal in time, a relaxing system for an optimisation.

Bringing analog and stochastic computing back is not nostalgia. Physics can sample, relax to a minimum or filter a signal using far less energy than a digital machine simulating the same process. That saving is a promise to be measured, not a result to be claimed. Answers from such hardware are also statistical, so they have to be certified against what a program asked for. vonNeuro is built around both problems: deciding which device should run a task, and keeping an honest record of what it cost and how far its answer can be trusted.

The core ideas

  • One program, any substrate. A program states what it means mathematically, not which chip you own. Each backend lowers that meaning to a native physical process, such as a coupling matrix, an anneal schedule or a driven circuit, instead of pretending the device is a CPU.
  • Three regimes, not one. Computation can minimise (relax to a ground state), sample (draw from a distribution) or evolve (run driven, far from equilibrium, as reservoirs, memristive networks and living tissue do). Equilibrium is one special case, and a sampler is not a failed optimiser.
  • Thermodynamic accounting. A figure in joules per task says little on its own. The goal is for every run to report its measured dissipation together with the thermodynamic lower bound it should be compared against, or to refuse the comparison when the two are not the same claim.
  • Physical includes biological. A backend qualifies if it can report its state, accept a drive and characterise its own noise. Neuronal cultures on electrode arrays, reaction networks and gene circuits can do all three, so they are part of the long-term design.

What runs today

The current bench is a proof of concept, not a product. It is a first prototype meant to show that the whole loop works on real, imperfect devices:

  • 16 memristors on two 16-pin devices, behind an analog multiplexer. Their far ends are biased at 2.47 V so they can be driven both ways through a 0–5 V multiplexer. They show measured pinched hysteresis loops, and users can sweep them online at up to ±1 V to keep them healthy for the next person.
  • 16 RC coprocessors on a second multiplexer that shares address lines with the first. This makes all 32 devices addressable remotely, one guarded measurement at a time.
  • A 16-p-bit hardware sampler that runs Gibbs sampling over up to sixteen Ising spins. You load couplings, set a temperature and stream samples.
  • VOLT 0.1, an early version of the vonNeuro language. You write a small system program and run it on a chosen device, for example memristor:15 or rc:2. The device contract is checked first: a program that needs an adaptive device is refused by an RC circuit, which names the failing clause. Each reply includes the compiled graph, the source hash and the energy measured at the device terminals.
  • CPU emulators of the analog, memristor, p-bit and spiking devices, used as digital references and as fallbacks when the bench is busy.

The measurements are made with an Analog Discovery Studio, and every raw sample is archived. The bench tools and client are currently tested on Windows with Python, and the Messenger server runs anywhere Python and FastAPI do.

vonNeuro Messenger and the open-source Python API

Messenger is the device server. It connects laboratory hardware, including one-off experimental chips, to user accounts on the web, without the lab having to redesign the device around a new architecture. You sign in, choose a job (a VOLT program, a memristor I–V sweep, an instrument capture, or an emulated experiment), follow it live and download the results, including every setting and device identity.

The Python client is open source under the MIT licence: github.com/vonneuro/messenger-api. It depends only on httpx. Every call goes through Messenger, which checks your account, the hardware switches and the voltage limits before anything is driven. 

pip install git+https://github.com/vonneuro/messenger-api.git
from vonneuro_messenger import MessengerClient

c = MessengerClient("https://series-marina-gigantic.ngrok-free.dev")
c.login("you", "your-password")

# run a VOLT 0.1 program on memristor 15 of the bench
reply = c.volt_run(program, {"u": 0.5}, "memristor:15")
print(reply["result"]["value"])      # measured terminal current
print(reply["measured_energy_j"])    # energy at the device terminals

If you would rather not install anything, a browser-based Python lab runs the same code with plots and downloads, and a script lab sends pulse scripts or Ising models straight to the bench. Runnable examples and the full bench manual are in the client repository. Add your GitHub username when you sign up to get access.

A small game that exercises everything

For fun, and as a test, I built a small Godot game, I Shall Survive. The enemies chasing the player run on RC coprocessors measured live on the bench. They fall back to calibrated emulators when the board is busy, use a real memristor to decide when to guard, and can draw their stochastic choices from the p-bit sampler. It is deliberately small, but it raises exactly the questions vonNeuro is built to answer: which device should take a task, what happens when it is unavailable, and whether the physical answer is still the right one.

Where it is going

The roadmap is the full operating system. It includes the VOLT compiler and a portable semantic graph, an event-driven kernel with a device registry, versioned device contracts that trigger recompilation when calibration drifts, and a thermodynamic ledger. Planned backends include GPUs (as the large-scale baseline that every physical run is compared against), p-bit fabrics on FPGA, quantum annealers, neuromorphic ASICs, memristive crossbars and nanowire meshes. Research targets include photonic operators, neuronal cultures and molecular reaction networks. Two further goals matter to me in particular. First, any lab should be able to connect its own chip through a lightweight adapter, keeping its existing control stack, and use Messenger to discover and characterise what the device can compute. Second, the design should be open enough that others can host their own instance on their own hardware.

How to get access

Create an account at vonneuro.com and open Messenger. Each account gets one hour of bench time, and more is available on request. You may see a warning that you are leaving the site. This is expected, because Messenger is currently served through a tunnel to the machine on my bench.

This is a side project, since during the day I work on quantum computing, and the bench is still a first prototype, cables and all. I am moving to a tidier soldered setup and will write about its evolution here and on LinkedIn. Feedback is very welcome.
